A guided course

Sudoku, inside out

This guide explains how the whole sudoku project works. It starts with the big picture. Then it follows each feature behind the screen: the sudoku engine, the app, the camera scan, the digit model and the backend.

Each chapter uses drawings first and words second. Click the diagrams, step through the animations and answer the small questions. The guide reads the real code, so the file names are true.

The project in one minute

The project is an iOS sudoku game without ads. It has three parts. Each part lives in its own folder and has its own language and tools.

Click any box to read what it does and where to learn more.

Game UI

The screens where the player plays: the board, the number keys, notes, undo, the timer and the stats. It asks @sudoku/core for every rule and hint. It saves each move to local storage.

Read more in Chapter 3.

Scan UI

The camera screen, the live outline of the grid, the lock-on, the transition animation and the correction screen. It uses the scanner, but it never sees the scanner internals.

Read more in Chapter 4.

Scanner module

Two jobs. On every camera frame, it finds the four corners of the grid. Once, after the capture, it cuts the photo into 81 cells and recognises each cell. Everything runs on the phone.

Read more in Chapter 4.

Local storage

An SQLite database on the phone. It holds the game in progress, the puzzle pool, the history and the settings. The app works fully without a network because of it.

Read more in Chapter 3.

The digit model

A small neural network in a .tflite file. It looks at one cell image and says two things: the digit (or empty) and the kind (printed, handwritten or notes).

Read more in Chapter 5.

Account and sync

Optional. When the player signs in, the app copies the history of finished games to the backend. A second phone then sees the same history. The game never waits for it.

Read more in Chapter 6.

@sudoku/core

Pure TypeScript with no screen, no files and no network. It knows the rules, solves any puzzle, makes new puzzles at a level and explains the next logical step as a hint. Pure code is easy to test.

Read more in Chapter 2.

ml/ (Python)

The workshop for the digit model. It builds the dataset, trains the network, measures it on whole sudoku photos and exports it. Today just install-model copies a model into the app. A promote gate (ADR-007, planned for M3) will copy it only when it is good enough.

Read more in Chapter 5.

Backend on AWS

A small Lambda function behind an API, a DynamoDB table for the history, and a bucket for scans that a player chooses to share. A kill switch stops it at the budget.

Read more in Chapter 6.

Follow one scan through the system

The best way to see how the parts fit is to follow one action. Step through what happens when the player scans a sudoku from a newspaper.

1. The camera looks for a grid

The camera gives about 30 frames per second. For each frame, the scanner looks for the largest square shape and returns its four corners. The screen draws an outline on top. When the corners stay still long enough, the app locks on. Chapter 4

2. The app takes one photo and flattens the grid

The camera takes one full-size photo. The scanner finds the corners again, more exactly. A homography then "unbends" the grid into a flat square, as if the photo came from straight above.

3. The model reads each cell

The flat grid becomes 81 small cell images of 64 × 64 pixels. The digit model reads each one: which digit, and is it printed, handwritten or notes? It also gives a confidence. Chapter 5

4. The player checks the result

The correction screen shows the recognised grid. The player fixes a wrong digit if necessary. @sudoku/core checks the rules and solves the puzzle. A puzzle without exactly one solution cannot start. Chapter 2

5. The player plays

The game screen loads the puzzle. Every move goes through one game session and goes into SQLite at once. If the app closes, nothing is lost. Chapter 3

6. The game ends up in the history

A finished game becomes a history entry. If the player has an account, the sync sends it to the backend later. If the player turned on "Help improve the app", the scan photo can go to the scan collection. Chapter 6
