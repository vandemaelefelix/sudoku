# App Icon and Dev Variant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Expo placeholder icon with the Op-art icon "Centred, in front of the waves". Add a development variant that installs beside the production app and shows a "DEV" ribbon.

**Architecture:** One Node script in `scripts/icons/` draws every icon layer as SVG in a 100 × 100 design space. It renders the layers to PNG with resvg. The 9 and the word "DEV" are outlines of the fonts the app already bundles, so the PNGs do not depend on the installed fonts. `app.json` holds the production config. A new `apps/mobile/app.config.ts` reads `APP_VARIANT` and changes the name, IDs, scheme and icons for the development variant.

**Tech Stack:** Expo SDK 57 (`@expo/config-types` 57.0.2), Node 24 with `node:test`, `@resvg/resvg-js` 2.6.2, `opentype.js` 1.3.4, Jest (`jest-expo`) for the app config.

**Spec:** GitHub issue [#92](https://github.com/vandemaelefelix/sudoku/issues/92) (add the app icon). The design: the card "Centred, in front of the waves" on the [icon studies page](https://claude.ai/artifact/Jkqyd3N2AVjAHMEwkpYqfj). The colours and the wave shape come from the Op-art theme (`apps/mobile/src/theme/themes/opart/palette.ts`, ADR-021).

## Global Constraints

- Branch `feature/92-app-icon` from `origin/develop`. Pull requests target `develop`. Commit this plan file in the first commit of the branch.
- Do not edit `ios/` or `android/` (ADR-002). All native config goes in `app.json`, `app.config.ts` or a config plugin.
- iOS light icon: 1024 × 1024 PNG, square, every pixel opaque, no rounded corners. iOS applies the mask.
- iOS dark and tinted icons: 1024 × 1024 PNG with a transparent ground. iOS draws the ground.
- Android adaptive icon: 108 dp canvas. Launchers show the centre 72 dp. Keep the foreground content inside the 66 dp safe circle: radius 30.5 units in the 100-unit design space.
- Production keeps the bundle ID `com.vandemaelefelix.sudoku`, the name "Sudoku" and the scheme `sudoku`.
- Development: bundle ID and Android package `com.vandemaelefelix.sudoku.dev`, the name "Sudoku Dev" and the scheme `sudoku-dev`.
- An unset `APP_VARIANT` means development. Any value other than `development` or `production` stops the build with an error.
- Pin new dependencies to an exact version (`--save-exact`).
- Rules in `AGENTS.md` and `apps/mobile/AGENTS.md` apply. Comments, docs and commit messages follow the Simplified Technical English rules. No TODO comments.
- Commits: Conventional Commits with `(#92)`. Do not push or open the pull request until the developer asks.
- Before done: `just lint`, `just typecheck`, `just test-ts` and `just docs-check` pass.

## Review Focus

1. **The light icon has a transparent pixel.** App Store Connect rejects an iOS icon with an alpha channel in use. Task 2 tests that every pixel of `ios-light.png` has alpha 255, for both variants.
2. **The Android launcher crops the 9 or the word "DEV".** A round mask shows only a circle. Task 1 tests that the scaled 9 and the strip text stay inside the 30.5-unit safe circle.
3. **The ribbon covers the 9 or a wave.** Task 1 tests that every wave crest and the 9's knockout box stay outside the iOS corner ribbon.
4. **A typo in `APP_VARIANT` builds the wrong app.** For example `APP_VARIANT=prod`. Task 3 tests that `appVariant('prod')` throws.
5. **A config path points to a PNG that does not exist.** The build then fails late, in Xcode. Task 3 tests that every icon and splash path of both variants exists on disk.

test('the 9 is centred and has the design height', () => {
  const { x1, y1, x2, y2 } = nine.box
  assert.ok(Math.abs((x1 + x2) / 2 - 50) < 0.01)
  assert.ok(Math.abs((y1 + y2) / 2 - 50) < 0.01)
  assert.ok(Math.abs(y2 - y1 - NINE.height) < 0.01)

  const ys = WAVES.map(([y]) => y)
  assert.equal((Math.min(...ys) + Math.max(...ys)) / 2, 50)

  const d = wavePath(50, 1, -2, 102)
  assert.match(d, /^M-2 /)
  assert.match(d, /L102 /)

  const { x1, y1, x2, y2 } = nine.box
  const box = { x1: x1 - KNOCKOUT, y1: y1 - KNOCKOUT, x2: x2 + KNOCKOUT, y2: y2 + KNOCKOUT }
  for (const [x, y] of corners(box).map(([x, y]) => scaled(x, y))) {
    assert.ok(Math.hypot(x - 50, y - 50) < SAFE_RADIUS, `corner ${x}, ${y}`)
  }

  const text = outline(mono, 'DEV', { cx: ANDROID_RIBBON.cx, cy: ANDROID_RIBBON.cy, height: ANDROID_RIBBON.textHeight })
  for (const [x, y] of corners(text.box)) assert.ok(Math.hypot(x - 50, y - 50) < SAFE_RADIUS, `corner ${x}, ${y}`)
  const [, nineBottom] = scaled(0, nine.box.y2 + KNOCKOUT)

  const c = IOS_RIBBON.cx - IOS_RIBBON.cy
  const nearEdge = c - (IOS_RIBBON.thickness / 2) * Math.SQRT2
  const { x1, y1, x2, y2 } = nine.box
  const box = { x1: x1 - KNOCKOUT, y1: y1 - KNOCKOUT, x2: x2 + KNOCKOUT, y2: y2 + KNOCKOUT }

  const r = 22.37
  const text = outline(mono, 'DEV', { cx: IOS_RIBBON.cx, cy: IOS_RIBBON.cy, height: IOS_RIBBON.textHeight })

  assert.match(svg, /<mask id="knockout"/)

```js
import { readFileSync } from 'node:fs'
import opentype from 'opentype.js'

const FONT_DIR = new URL('../../apps/mobile/assets/fonts/', import.meta.url)

// The fonts the app bundles (ADR-021). The icon uses the same 9 as a given digit of the Op-art theme.
export const FONTS = {
  serif: new URL('InstrumentSerif-Regular.ttf', FONT_DIR),
  mono: new URL('IBMPlexMono-Medium.ttf', FONT_DIR),
}

export function loadFont(url) {
  const bytes = readFileSync(url)
  return opentype.parse(bytes.buffer.slice(bytes.byteOffset, bytes.byteOffset + bytes.byteLength))
}

/** The outline of `text` as SVG path data. Its ink box is centred on (cx, cy) and is `height` units high. */
export function outline(font, text, { cx, cy, height }) {
  const probe = font.getPath(text, 0, 0, 100).getBoundingBox()
  const size = (100 * height) / (probe.y2 - probe.y1)
  const box = font.getPath(text, 0, 0, size).getBoundingBox()
  const path = font.getPath(text, cx - (box.x1 + box.x2) / 2, cy - (box.y1 + box.y2) / 2, size)
  return { d: path.toPathData(3), box: path.getBoundingBox() }
}
```

```js
// The icon design "Centred, in front of the waves" (#92), in a 100 × 100 design space.
// Colours from the Op-art theme palette (ADR-021).

/** [centre y, amplitude] of the 4 waves. Each lower wave swings more, like the Op-art panel edge. */
export const WAVES = [
  [36.5, 1],
  [45.5, 1.6],
  [54.5, 2.2],
  [63.5, 2.8],
]
export const WAVE_PERIOD = 24
export const WAVE_WIDTH = 3
/** The 9: centre and ink height in design units. */
export const NINE = { cx: 50, cy: 50, height: 58 }
/** Design units of empty space between the 9 and a wave. */
export const KNOCKOUT = 3.5
/** Android shows the centre 72 dp of the 108 dp adaptive layer. */
export const ANDROID_SCALE = 72 / 108
/** The 66 dp safe circle of the 108 dp layer, as a radius in design units. */
export const SAFE_RADIUS = (33 / 108) * 100
/** A band across the top-right corner, at 45°. Its centre line is x - y = cx - cy. */
export const IOS_RIBBON = { cx: 88, cy: 12, length: 80, thickness: 11, textHeight: 5.5, rotate: 45 }
/** A horizontal strip below the scaled 9. A round launcher mask cuts its ends, which is intended. */
export const ANDROID_RIBBON = { cx: 50, cy: 76.5, length: 120, thickness: 8, textHeight: 4.5, rotate: 0 }

/** ground null: transparent, iOS or the launcher draws the ground. */
export const PALETTES = {
  light: { ground: '#ffffff', digit: '#0f1d5c', waves: '#1f3fd1', ribbon: '#1f3fd1' },
  dark: { ground: null, digit: '#ffffff', waves: '#c3cbef', ribbon: '#1f3fd1' },
  tinted: { ground: null, digit: '#ffffff', waves: '#b3b3b3', ribbon: '#ffffff' },
  mono: { ground: null, digit: '#ffffff', waves: '#ffffff', ribbon: '#ffffff' },
}

const r = (n) => +n.toFixed(2)

/** A sine wave from x0 to x1, one point per unit. Same formula as wavePoints in the app (ADR-021). */
export function wavePath(y, amp, x0, x1) {
  const points = []
  for (let x = x0; x <= x1; x += 1) points.push(`${r(x)} ${r(y - amp * Math.sin((2 * Math.PI * x) / WAVE_PERIOD))}`)
  return `M${points.join(' L')}`
}

/** The band rectangle with the text cut out. Draw it with fill-rule evenodd, so the text shows the layer below. */
export function ribbonPath(text, { cx, cy, length, thickness }) {
  const x = cx - length / 2
  const y = cy - thickness / 2
  return `M${r(x)} ${r(y)} H${r(x + length)} V${r(y + thickness)} H${r(x)} Z ${text.d}`
}

export function iconSvg({ palette, layers, nine, scale = 1, ribbon = null }) {
  const p = PALETTES[palette]
  // Wide enough that the waves still run past the edge after the scale.
  const x0 = 50 - 52 / scale
  const x1 = 50 + 52 / scale
  const defs = []
  const content = []
  if (layers.includes('waves')) {
    // The mask is in the coordinates of the scaled group, the same as the 9.
    defs.push(
      `<mask id="knockout" maskUnits="userSpaceOnUse" x="-100" y="-100" width="300" height="300">` +
        `<rect x="-100" y="-100" width="300" height="300" fill="#ffffff"/>` +
        `<path d="${nine}" fill="#000000" stroke="#000000" stroke-width="${2 * KNOCKOUT}" stroke-linejoin="round"/>` +
        `</mask>`,
    )
    const d = WAVES.map(([y, amp]) => wavePath(y, amp, x0, x1)).join(' ')
    content.push(
      `<path d="${d}" fill="none" stroke="${p.waves}" stroke-width="${WAVE_WIDTH}" stroke-linecap="round" mask="url(#knockout)"/>`,
    )
  }
  if (layers.includes('nine')) content.push(`<path d="${nine}" fill="${p.digit}"/>`)
  const ground = layers.includes('ground') ? `<rect width="100" height="100" fill="${p.ground}"/>` : ''
  const body = scale === 1 ? content.join('') : `<g transform="translate(50 50) scale(${scale}) translate(-50 -50)">${content.join('')}</g>`
  const band = ribbon
    ? `<path d="${ribbon.d}" fill="${p.ribbon}" fill-rule="evenodd" transform="rotate(${ribbon.rotate} ${ribbon.cx} ${ribbon.cy})"/>`
    : ''
  return `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100"><defs>${defs.join('')}</defs>${ground}${body}${band}</svg>`
}
```

```js
import resvg from '@resvg/resvg-js'
import { ANDROID_RIBBON, ANDROID_SCALE, IOS_RIBBON, NINE, iconSvg, ribbonPath } from './geometry.mjs'
import { FONTS, loadFont, outline } from './glyph.mjs'

const { Resvg } = resvg

function ribbonFor(mono, spec) {
  const text = outline(mono, 'DEV', { cx: spec.cx, cy: spec.cy, height: spec.textHeight })
  return { d: ribbonPath(text, spec), rotate: spec.rotate, cx: spec.cx, cy: spec.cy }
}

/** Every PNG of the app icon, the splash and the favicon (ADR-022). */
export function buildIcons() {
  const nine = outline(loadFont(FONTS.serif), '9', NINE).d
  const mono = loadFont(FONTS.mono)
  const iosRibbon = ribbonFor(mono, IOS_RIBBON)
  const androidRibbon = ribbonFor(mono, ANDROID_RIBBON)
  const all = ['ground', 'waves', 'nine']
  const marks = ['waves', 'nine']

  const variant = (folder, dev) => [
    { file: `${folder}/ios-light.png`, size: 1024, svg: iconSvg({ palette: 'light', layers: all, nine, ribbon: dev ? iosRibbon : null }) },
    { file: `${folder}/ios-dark.png`, size: 1024, svg: iconSvg({ palette: 'dark', layers: marks, nine, ribbon: dev ? iosRibbon : null }) },
    { file: `${folder}/ios-tinted.png`, size: 1024, svg: iconSvg({ palette: 'tinted', layers: marks, nine, ribbon: dev ? iosRibbon : null }) },
    {
      file: `${folder}/android-foreground.png`,
      size: 1024,
      svg: iconSvg({ palette: 'light', layers: ['nine'], nine, scale: ANDROID_SCALE, ribbon: dev ? androidRibbon : null }),
    },
    {
      file: `${folder}/android-monochrome.png`,
      size: 1024,
      svg: iconSvg({ palette: 'mono', layers: marks, nine, scale: ANDROID_SCALE, ribbon: dev ? androidRibbon : null }),
    },
  ]

  return [
    ...variant('production', false),
    ...variant('development', true),
    // The waves in the background layer keep the knockout of the 9 in the foreground layer.
    { file: 'production/android-background.png', size: 1024, svg: iconSvg({ palette: 'light', layers: ['ground', 'waves'], nine, scale: ANDROID_SCALE }) },
    { file: 'splash/splash-light.png', size: 1024, svg: iconSvg({ palette: 'light', layers: marks, nine }) },
    { file: 'splash/splash-dark.png', size: 1024, svg: iconSvg({ palette: 'dark', layers: marks, nine }) },
    { file: 'favicon.png', size: 48, svg: iconSvg({ palette: 'light', layers: all, nine }) },
  ]
}

/** Renders one icon. pixels: RGBA bytes, row by row. */
export function renderPng({ svg, size }) {
  const image = new Resvg(svg, { fitTo: { mode: 'width', value: size } }).render()
  return { width: image.width, height: image.height, pixels: image.pixels, png: image.asPng() }
}
```

```ts
import type { ConfigContext, ExpoConfig } from 'expo/config'

export type AppVariant = 'development' | 'production'

const DEV_ICONS = './assets/icons/development'

/** ADR-022: an unset APP_VARIANT means development, so a plain `expo run:ios` never replaces the production app. */
export function appVariant(value: string | undefined): AppVariant {
  if (value === undefined || value === '' || value === 'development') return 'development'
  if (value === 'production') return 'production'
  throw new Error(`APP_VARIANT must be "development" or "production", not "${value}"`)
}

function required(value: string | undefined, key: string): string {
  if (value === undefined) throw new Error(`app.json has no ${key}`)
  return value
}

/** app.json is the production config. The development variant installs beside it (ADR-022). */
export function variantConfig(config: ExpoConfig, variant: AppVariant): ExpoConfig {
  if (variant === 'production') return config
  return {
    ...config,
    name: `${config.name} Dev`,
    scheme: 'sudoku-dev',
    icon: `${DEV_ICONS}/ios-light.png`,
    ios: {
      ...config.ios,
      bundleIdentifier: `${required(config.ios?.bundleIdentifier, 'ios.bundleIdentifier')}.dev`,
      icon: {
        light: `${DEV_ICONS}/ios-light.png`,
        dark: `${DEV_ICONS}/ios-dark.png`,
        tinted: `${DEV_ICONS}/ios-tinted.png`,
      },
    },
    android: {
      ...config.android,
      package: `${required(config.android?.package, 'android.package')}.dev`,
      adaptiveIcon: {
        ...config.android?.adaptiveIcon,
        foregroundImage: `${DEV_ICONS}/android-foreground.png`,
        monochromeImage: `${DEV_ICONS}/android-monochrome.png`,
      },
    },
  }
}

// app.json always holds name and slug, so the config is a full ExpoConfig here.
export default ({ config }: ConfigContext): ExpoConfig =>
  variantConfig(config as ExpoConfig, appVariant(process.env.APP_VARIANT))
```

Create `docs/architecture/adr/adr-022-app-variants.md`:

```markdown
---
status: DRAFT
---

# ADR-022: Two app variants and an icon generated from the Op-art theme

| Field   | Value      |
| ------- | ---------- |
| Project | Sudoku     |
| Status  | Proposed   |
| Date    | 2026-10-14 |
| Contact | Felix      |

## Context

The app used the Expo placeholder icon. Every build also used one bundle ID, so a development build
replaced the production app on the phone, with its saved games. The developer cannot see which build
is installed.

The icon must follow the iOS rules (an opaque 1024 px light icon, plus dark and tinted icons) and the
Android rules (an adaptive icon with a safe zone, plus a monochrome layer).

## Alternatives Evaluated

| Option | For | Against |
| --- | --- | --- |
| One variant, a ribbon only in development builds | No new bundle ID | The two builds still replace each other. The ribbon shows only what is installed now |
| Two variants, unset `APP_VARIANT` means production | The Expo tutorial default | A plain `expo run:ios`, the daily command, replaces the production app |
| **Two variants, unset `APP_VARIANT` means development** | A local build never touches the production app | A release build must set `APP_VARIANT=production`. `just ios-release` does it |
| Icon PNGs drawn by hand in a design tool | No script | Each change repeats for 14 files. The 9 drifts from the theme font |
| **Icon PNGs generated from one SVG design** | One source. The 9 is the Instrument Serif outline | Two development dependencies: resvg and opentype.js |

## Decision

1. `app.json` holds the production config. `app.config.ts` reads `APP_VARIANT`.
2. An unset or empty `APP_VARIANT` means development. An unknown value stops the build.
3. The development variant has the bundle ID and Android package `com.vandemaelefelix.sudoku.dev`,
   the name "Sudoku Dev", the scheme `sudoku-dev` and icons with a "DEV" ribbon.
4. `scripts/icons/` draws every icon layer in one 100 × 100 design. `just icons` renders the PNGs
   into `apps/mobile/assets/icons/`. The PNGs are committed.
5. The splash screen shows a still image of the mark until #93 (animate the splash screen).

## Consequences

- The first development build installs as a new app. Its data starts empty. The production app keeps
  its data.
- A change of variant needs `expo prebuild --clean`, because `ios/` keeps the last bundle ID. The
  `just ios-dev` and `just ios-release` recipes do this.
- `just pull-scans` takes the bundle ID of the variant.
- iOS applies the iOS 26 glass effect to the PNG icon. An Icon Composer `.icon` file is not used.

## Reassessment Triggers

- EAS Build is adopted (ADR-010): move `APP_VARIANT` into the build profiles of `eas.json`.
- A preview variant for testers is needed.
- Icon Composer files become available from a script: replace the iOS PNGs with a `.icon` file.
```
